# 网约车保险风控方案 - 决策支持工具包

**使用说明**: 本工具包为风控总监设计，包含谈判、尽调、评估各环节的实用工具

---

## 📋 工具1: 商务谈判要点清单

### 🎯 核心谈判目标

#### 必须争取的条款（硬底线）
```
1. 业绩对赌机制
   ✅ 承诺赔付率降低≥15% → 100%付费
   ✅ 降低10-15% → 80%付费  
   ✅ 降低<10% → 50%付费或终止合作
   ✅ 数据来源问题导致效果不达标 → 免费重试

2. 数据安全保障
   ✅ 数据所有权归属：我司
   ✅ 智车不得将数据用于其他用途
   ✅ 合作终止后30天内销毁所有数据
   ✅ 因数据违规导致的损失由智车全额承担
   ✅ 提供数据处理合规意见书

3. 技术交接条款
   ✅ 合作满2年后，我司有权以市场价收购模型源码
   ✅ 或要求智车培训我司内部团队（6个月交接期）
   ✅ 避免永久技术绑定

4. 排他性保护
   ✅ 智车在我司所在省份不得同时服务2家以上保司
   ✅ 四川车联不得同时代理直接竞品
   ✅ 违约赔偿：年服务费的3倍
```

#### 可以妥协的条款（软底线）
```
1. 付费方式
   优先级: 按效果分成 > 按件计费 > 固定年费
   可接受: 混合模式（基础费+分成）

2. 试点规模
   期望: 3省同时启动
   可接受: 1省试点，3个月后扩展

3. 交叉持股
   期望: 占智车5-10%股份
   可接受: 现金合作，无股权绑定

4. 服务期限
   期望: 3年框架协议
   可接受: 1年+续约选择权
```

#### 坚决拒绝的条款（红线）
```
❌ 预付款比例超过50%
❌ 排除业绩对赌条款
❌ 数据权属模糊或归属智车
❌ 无明确退出机制
❌ 要求我司承担数据合规责任
❌ 禁止我司自研类似系统
```

### 💼 谈判策略与话术

#### 开场策略
```
"我们非常认可智车的技术实力和市场地位，希望能够建立长期战略合作。
但作为上市公司，我们必须在合规、风控、财务三方面满足要求。
希望我们能找到一个双赢的合作模式。"
```

#### 关键博弈点

**1. 数据合规问题**
```
我方: "我们对9大风险因子的数据来源和合规性有疑虑"
对方预期: "这是商业机密"
我方回应: "不提供具体数据源可以，但必须提供合规法律文件
         和数据使用授权证明。这是合作的先决条件。"
```

**2. 效果保证**
```
我方: "Lift=2.17在行业里属于什么水平？"
对方预期: "属于优秀水平"
我方回应: "据我们了解，行业优秀模型Lift通常在3-5。
         如果效果达不到行业优秀水平，我们希望有相应的价格调整。"
```

**3. 技术依赖**
```
我方: "如果数据源断供，有什么应急方案？"
对方预期: "不会断供"
我方回应: "我们需要有Plan B。比如降级模型版本，
         或者多数据源备份。这必须写入合同。"
```

## 🛡️ 工具2: 风险检查表

### 🔴 高风险项目（一票否决）

#### 数据合规风险
```
□ 9大风险因子的数据来源是否明确？
□ 是否获得数据使用授权书？
□ 是否有律所出具的合规意见书？
□ 是否涉及《个人信息保护法》保护的敏感信息？
□ 数据跨境传输是否符合规定？
□ 用户是否获得充分告知并同意？
□ 数据存储和传输是否加密？
□ 数据保留期限是否符合法规？
```

**评估标准**: 
- 3项以上未通过 → 一票否决
- 1-2项未通过 → 暂停谈判，要求补充材料

#### 技术可行性风险
```
□ 模型Lift值是否达到2.0以上？
□ 是否有独立的第三方验证？
□ 技术团队是否有成功案例？
□ 系统架构是否稳定可靠？
□ 是否有技术备份方案？
□ API接口是否标准化？
□ 系统响应时间是否满足要求？
□ 数据处理能力是否满足业务量？
```

**评估标准**:
- Lift值<2.0 → 重新谈判或拒绝
- 3项以上未通过 → 要求技术改进后再议

## 🧮 工具3: 技术评估框架

### 📊 模型效果评估

#### 核心指标
```
1. Lift值（区分度）
   - 优秀: >3.0
   - 良好: 2.0-3.0  
   - 及格: 1.5-2.0
   - 不及格: <1.5

2. AUC值（预测准确度）
   - 优秀: >0.8
   - 良好: 0.7-0.8
   - 及格: 0.6-0.7
   - 不及格: <0.6

3. 稳定性（时间维度）
   - 优秀: 6个月无明显衰减
   - 良好: 3个月无明显衰减
   - 及格: 1个月无明显衰减
   - 不及格: 1个月内明显衰减
```

#### 验证方法
```
1. 历史数据回测
   - 用我司历史数据测试模型效果
   - 对比实际赔付率vs预测赔付率
   - 计算KS值、Gini系数等评估指标

2. A/B测试
   - 选择部分保单使用新模型
   - 对比实验组vs对照组的赔付率差异
   - 统计学检验显著性水平

3. 交叉验证
   - K-fold交叉验证评估模型泛化能力
   - 时间序列验证评估模型稳定性
   - 不同地区验证评估模型适应性
```

### 🛠️ 技术实现评估

#### 系统架构
```
□ 部署方式（SaaS/私有化/混合）
□ 接口标准（RESTful/API/文件）
□ 数据格式（JSON/XML/CSV）
□ 响应时间（<100ms为优）
□ 并发能力（支持多少QPS）
□ 扩展性（水平扩展能力）
□ 可用性（SLA承诺）
□ 安全性（加密/认证/审计）
```

#### 数据要求
```
我司需要提供的数据:
□ 保单信息（保费、期限、险种）
□ 客户信息（年龄、性别、驾龄）
□ 车辆信息（品牌、车型、车龄）
□ 历史理赔（出险时间、金额、责任）
□ 历史违章（时间、类型、扣分）

智车需要提供的数据:
□ 风险评分（0-100分）
□ 风险等级（1-10级）
□ 9大因子原始值
□ 评分解释（为何评为该分数）
□ 置信区间（评分的可靠程度）
□ 模型版本和更新时间
```

#### 对接复杂度评估
```
开发工作量评估:
□ API对接开发（2人周）
□ 数据清洗和转换（1人周）
□ 系统集成测试（1人周）
□ 用户界面开发（1人周）
□ 文档和培训（0.5人周）
总计: 5.5人周（约1.5个月）

风险点:
□ 数据格式不匹配 → 延期1周
□ 接口不稳定 → 延期2周  
□ 性能不达标 → 优化1个月
□ 安全审查不通过 → 重做2个月
```

### 📈 技术创新评估

#### 技术先进性
```
算法水平:
□ 机器学习算法（XGBoost/LightGBM）
□ 深度学习（神经网络）
```

## 💰 工具4: ROI测算模型

### 📊 基础财务模型

#### 成本测算
```
一次性成本:
□ 软件采购费: 50万
□ 系统对接费: 30万  
□ 培训费: 10万
□ 合规审查费: 10万
总计: 100万

年度成本:
□ 服务费: 按保费收入2-5%
□ 维护费: 10万/年
□ 升级费: 20万/年
□ 人员成本: 30万/年（1个专职人员）
总计: 基础成本 + 保费收入×(2-5%)
```

#### 收益测算
```
直接收益:
□ 赔付率降低 × 保费收入
□ 减少核保成本
□ 提高风险识别效率

间接收益:
□ 提升品牌声誉
□ 增强获客能力
□ 积累数据资产
□ 技术能力提升
```

#### 敏感性分析
```
情景分析（以年保费10亿为例）:

保守情景:
- 赔付率降低: 8%
- 服务费率: 5%
- 年收益: 800万 - 500万 = 300万
- ROI: 300万/130万 = 231%

基准情景:
- 赔付率降低: 15%  
- 服务费率: 3%
- 年收益: 1500万 - 300万 = 1200万
- ROI: 1200万/130万 = 923%

乐观情景:
- 赔付率降低: 20%
- 服务费率: 2%
- 年收益: 2000万 - 200万 = 1800万
- ROI: 1800万/130万 = 1385%
```
