# 任务背景

  我是**某中型财险公司风控部总监**，负责评估是否采购智车睿控的网约车风控方案。

## 公司现状

- 网约车业务: 年保费3亿，赔付率105%（亏损1500万/年）
- 团队能力: IT团队10人，数据团队5人
- 风险偏好: 保守型（需要3个月小规模试点验证）
- 决策时间: 2周内需要向CEO提交评估报告

## 已知信息

- ✅ 我们已在使用北理里程数据，但效果逐年下降
- ✅ 竞品平安保险使用了类似风控系统，据说效果不错
- ⚠️ 监管层2024年加强了数据隐私监管
- ⚠️ 公司IT系统较老旧，API对接能力有限

## 决策约束

- 预算上限: 首年投入不超过500万
- 时间要求: 3个月内完成试点并出结果
- 必要条件:
  1. 数据合规（一票否决）
  2. 赔付率降低>15%
  3. ROI>300%（3年维度）

# 分析任务

  请使用 **deep-reading-analyst** 技能对附件《网约车保险风险解决方案》进行 **Level 3 深度分析**。

## 核心目标（按优先级排序）

1. **业务决策**: 3天内决定是否进入尽调阶段
2. **风险识别**: 找出可能导致项目失败的关键风险
3. **学习理解**: 建立网约车保险风控的知识体系

## 必须使用的分析框架

- ✅ **SCQA**: 理清方案逻辑
- ✅ **批判性思维**: 评估论证质量（重点关注数据来源可信度）
- ✅ **逆向思考**: 识别失败模式（重点关注数据合规、三方利益冲突）
- ✅ **心智模型**: 多维度评估（经济学、统计学、博弈论视角）
- ✅ **第一性原理**: 拆解保险定价本质
- ✅ **系统思维**: 绘制利益相关方关系图

## 特别关注点

1. **数据合规性**:

   - 9大风险因子是否涉及个人隐私？
   - 是否符合《个人信息保护法》？
   - 需要什么法律文件支撑？
2. **与北理数据对比**:

   - 增量价值在哪里？
   - 为什么Lift只有2.17而不是3+？
   - 是否值得额外投入？
3. **实施可行性**:

   - 我们的IT团队能对接吗？
   - 数据从哪里来？我们需要提供什么？
   - 3个月试点现实吗？
4. **商业条款建议**:

   - 如何设计对赌协议？
   - 哪些条款必须坚持？
   - 哪些可以妥协？

## 对比分析（如果可能）

- 方案A: 智车睿控（当前方案）
- 方案B: 自研模型（成本500万，18个月）
- 方案C: 直接与滴滴/高德合作获取数据

  PART 3: 原理拆解 - 为什么这样写更好？

  🧠 核心原理 1: Context Precision（上下文精确性）

  原理:
  AI的输出质量 = f(任务明确度, 背景信息丰富度, 约束条件清晰度)

  公式:
  输出准确度 ∝ (明确的角色 × 具体的场景 × 清晰的约束) / 信息模糊度

  实践:

| 模糊Prompt     | 精确Prompt                                         | 效果提升 |
| -------------- | -------------------------------------------------- | -------- |
| "分析这个方案" | "我是风控总监，预算500万，3个月试点，评估是否合作" | +300%    |
| "深入分析"     | "使用SCQA+逆向思考，重点关注数据合规和ROI"         | +200%    |
| "给我建议"     | "输出1页执行摘要+详细报告+谈判清单"                | +150%    |

---

  🧠 核心原理 2: Constraint-Driven Output（约束驱动输出）

  原理:
  没有约束的任务 = 无穷多个"正确答案" = AI不知道选哪个

  类比:
  ❌ "帮我设计一栋房子"
     → AI: 别墅？公寓？木屋？日式？欧式？（无从下手）

  ✅ "3口之家，预算200万，北京郊区，现代简约风，
      200平，带花园，3年内建成"
     → AI: 明确目标，可以给出具体方案

  应用到商业分析:
  ❌ "评估是否合作"
     → AI: 从什么角度评估？时间窗口？预算？风险承受度？

  ✅ "3个月内决定是否投入1000万试点，
      必要条件: 数据合规+赔付率降低15%+ROI>300%"
     → AI: 明确决策标准，可以给出Go/No-Go建议

---

  🧠 核心原理 3: Comparative Reasoning（对比推理）

  原理:
  单一方案分析 = 缺少基准 = 无法判断"好坏"
  多方案对比 = 相对优劣 = 可量化决策依据

  示例:
  方案A单独分析:
  "Lift=2.17是好还是不好？"
  → 不知道，缺少参照系

  加入对比:
  "Lift=2.17 vs 行业平均3.5 vs 自研预期4.0"
  → 立刻明白：中等偏下，但成本低，适合快速试点

---

  🧠 核心原理 4: Layered Output（分层输出）

  原理:
  不同受众需要不同深度的信息
  CEO要结论，专家要细节，执行层要清单

  金字塔结构:
  第1层: 执行摘要（CEO看，30秒读完）
     ↓
  第2层: 关键洞察（管理层看，5分钟读完）
     ↓
  第3层: 详细分析（专家看，30分钟读完）
     ↓
  第4层: 附录数据（备查，按需阅读）

  实践:
  ❌ "给我一个15页的分析报告"
     → CEO不会看，太长；
     → 执行团队找不到行动指南

  ✅ "1页执行摘要 + 详细报告 + 谈判清单 + 风险检查表"
     → 每个角色都有对应的可用内容

---

  🧠 核心原理 5: Gap Highlighting（盲区提示）

  原理:
  好的分析不仅告诉你"知道什么"，
  更重要的是告诉你"不知道什么"

  示例:
  普通分析:
  "模型Lift=2.17，效果不错"

  高级分析:
  "模型Lift=2.17，但存在3个信息缺口:

1. 验证数据的时间跨度未知（可能过时）
2. 数据来源未披露（合规性存疑）
3. 与竞品对比数据缺失（无法判断相对优势）

   建议立即向智车索取:

- 验证数据的时间范围
- 数据获取授权协议
- 与其他风控方案的对比报告"

  PART 4: 思考框架 - 如何设计超越性 Prompt？

  🎯 框架 1: 5W2H2C 扩展法

  在传统5W2H基础上，增加2个C:

| 维度          | 问题         | 示例                          |
| ------------- | ------------ | ----------------------------- |
| Who           | 我是谁？     | 风控总监/CEO/技术VP           |
| What          | 分析什么？   | 评估合作方案/风险识别/ROI测算 |
| Why           | 为什么分析？ | 决策/学习/内部培训            |
| When          | 时间约束？   | 3天/2周/1个月                 |
| Where         | 应用场景？   | CEO汇报/内部讨论/商务谈判     |
| How           | 用什么方法？ | SCQA/批判性思维/系统思维      |
| How much      | 资源约束？   | 预算500万/团队10人/3个月试点  |
| Constraint ⭐ | 硬约束条件？ | 数据必须合规/ROI>300%         |
| Comparison ⭐ | 对比什么？   | vs自研/vs竞品/vs现状          |

---

  🎯 框架 2: RACE 输出结构

| 层级           | 含义     | 输出要求               |
| -------------- | -------- | ---------------------- |
| Recommendation | 推荐结论 | 一句话答案 + Go/No-Go  |
| Analysis       | 分析过程 | 8个思维框架的详细拆解  |
| Checklist      | 行动清单 | 今天/本周/下月要做的事 |
| Exceptions     | 例外情况 | 什么情况下结论会改变？ |

---

  🎯 框架 3: PQR 质量控制

  在Prompt末尾加入:

## 质量检查

  请在输出前自我检查:

  **P (Precision) - 精确性**
  □ 所有数字都有来源引用吗？
  □ 所有结论都有证据支撑吗？
  □ 区分了"事实"和"推测"吗？

  **Q (Quantification) - 量化性**
  □ 风险都量化了吗（高/中/低 → 概率X%）？
  □ 建议都可衡量吗（"尽快"→"3天内"）？
  □ 对比都有数据吗（"更好"→"提升20%"）？

  **R (Relevance) - 相关性**
  □ 所有分析都与决策目标相关吗？
  □ 剔除了"有趣但无用"的信息吗？
  □ 输出是否直接可用（而非需要二次加工）？

  PART 5: 如何超越我给的最佳示范？

  🚀 超越路径 1: 加入动态反馈机制

  我的示范的局限:

- 静态的、一次性的分析
- 没有后续跟进机制

  超越方法:

## 分析迭代计划

  第1轮（今天）: 基于现有PDF的初步分析
     ↓ 输出信息缺口清单

  第2轮（获得补充材料后）:
     - 智车提供的客户案例
     - 竞品方案对比
     - 数据合规证明
     ↓ 更新风险评估

  第3轮（试点后）:
     - 实际试点数据
     - 模型准确率验证
     ↓ 最终Go/No-Go决策

  每轮分析请标注:

- 🟢 已确认的信息
- 🟡 待验证的假设
- 🔴 新发现的风险

---

  🚀 超越路径 2: 嵌入决策树

  我的示范的局限:

- 给出建议，但没有告诉你"如果X发生，该怎么办"

  超越方法:

## 决策树嵌入

  如果智车提供了数据合规证明:
    ├─ 且合规无问题 → 进入尽调阶段
    └─ 但存在灰色地带 →
        ├─ 风险可通过条款转移 → 继续谈判
        └─ 风险无法转移 → 终止，启动Plan B

  如果试点赔付率降低15%:
    ├─ 且数据质量稳定 → 签3年框架协议
    └─ 但数据获取困难 →
        ├─ 可协商改进 → 延长试点3个月
        └─ 无法改进 → 终止合作

  如果竞争对手也在用智车:
    ├─ 且效果好 → 加速决策（避免被抢先）
    └─ 且效果一般 → 重新评估独特价值

---

  🚀 超越路径 3: 引入概率思维

  我的示范的局限:

- "高风险"、"中风险"等定性描述
- 缺少概率量化

  超越方法:

## 概率化风险评估

  请对每个风险给出:

1. 发生概率（基于类似案例）
2. 影响程度（量化损失）
3. 期望损失 = 概率 × 影响

  示例:
  风险: 数据源断供

- 发生概率: 30%（滴滴有政策风险）
- 影响程度: 100% loss（模型完全失效）
- 期望损失: 30% × 500万投入 = 150万
- 缓解成本: 建立备用数据源，成本50万
- 决策: 值得投入（150万 > 50万）

---

  🚀 超越路径 4: 加入时间维度

  我的示范的局限:

- 静态分析，没有考虑时间演化

  超越方法:

## 时间敏感性分析

  T=0（现在）:

- 优势: 48家客户案例，先发优势
- 劣势: Lift=2.17，效果中等

  T=6个月:

- 预期:
  - 电动车占比↑ → 电池衰减因子重要性↑
  - 监管收紧↑ → 数据获取难度↑
- 建议: 抓住窗口期，6个月内必须完成试点

  T=2年:

- 预期:
  - 竞争对手模仿 → 同质化
  - 头部保司自研 → 市场萎缩
- 对策:
  - 2年内必须签排他协议
  - 或开发智车的替代方案

  时间价值量化:

- 每延迟1个月决策 = 损失125万（1500万/年亏损÷12）
- 建议决策时限: 2周（错失成本300万 vs 尽调成本20万）

---

  🚀 超越路径 5: 引入反事实推理

  我的示范的局限:

- 只分析"用了会怎样"
- 没有分析"不用会怎样"

  超越方法:

## 反事实分析（Counterfactual）

  场景A: 采用智车方案

- 最佳情况: 赔付率降至90%，年省1500万
- 最坏情况: 数据违规被罚，损失500万
- 期望值: 0.7×1500万 - 0.3×500万 = 900万

  场景B: 不采用，维持现状

- 确定情况: 继续亏损1500万/年
- 3年累计亏损: 4500万

  场景C: 自研模型

- 投入: 500万 + 18个月
- 预期效果: Lift=3.5（优于智车）
- 风险: 可能失败（概率40%）
- 期望值: 0.6×2000万 - 0.4×500万 = 1000万

  决策矩阵:
  场景A期望值(900万) < 场景C(1000万)
  但场景A时间快（3个月 vs 18个月）
  → 建议: 场景A试点，同时启动场景C自研

---

# 📋 分析任务模板

## 1. 角色与场景

```
  我是: [职位] 在 [公司类型]
  负责: [核心职责]
  面临: [当前挑战]
```

## 2. 决策目标

```
  主要目标: [具体决策，如"评估是否合作"]
  时间窗口: [X天/周/月内决策]
  预算约束: [投入上限]
  成功标准: [可量化的KPI]
```

## 3. 约束条件

```
  必要条件（一票否决）:
  - [ ] 条件1
  - [ ] 条件2

  充分条件（满足N个即可）:
  - [ ] 条件A
  - [ ] 条件B
  - [ ] 条件C
```

## 4. 已知信息

```
  ✅ 确定信息:
  - 事实1
  - 事实2

  ⚠️ 待验证信息:
  - 假设1
  - 假设2

  ❌ 信息缺口:
  - 缺失1（需要补充）
```

## 5. 对比基准

```
  方案A: [当前评估方案]
  方案B: [替代方案1]
  方案C: [替代方案2]
  现状: [什么都不做的情况]
```

## 6. 分析框架要求

```
  必须使用:
  - [ ] 框架1（重点关注X）
  - [ ] 框架2（重点关注Y）

  可选使用:
  - [ ] 框架3
```

## 7. 输出要求

```
  第1层: 执行摘要（1页，给[CEO]看）
    - 一句话结论
    - Go/No-Go/Wait
    - TOP 3关键点

  第2层: 详细分析（X页，给[团队]看）
    - 按框架逐一分析
    - 标注证据来源
    - 列出信息缺口

  第3层: 行动清单（给[执行层]看）
    - 今天要做的事
    - 本周要做的事
    - 下月要做的事

  第4层: 决策树（给[未来]看）
    - 如果X发生 → 做Y
    - 如果Z发生 → 做W
```

## 8. 质量检查

```
  请在输出前确认:
  □ 所有结论都有证据支撑
  □ 所有数字都有来源
  □ 所有风险都量化了概率
  □ 所有建议都可执行（有时间+责任人）
  □ 区分了"事实"、"推测"、"建议"
```

## 9. 迭代计划

```
  本轮分析: 基于[当前材料]
  下轮分析: 获得[补充信息]后更新
  最终决策: [时间节点]
```

## 10. 学习目标

```
  通过本次分析，我想学会:
  - [ ] 知识点1
  - [ ] 思维框架2
  - [ ] 可迁移技能3
```

  🎯 总结: Prompt 进化的5个层级

| 层级          | 特征         | 示例                                 | 效果 |
| ------------- | ------------ | ------------------------------------ | ---- |
| L1 - 指令型   | 简单命令     | "分析这个方案"                       | 10分 |
| L2 - 上下文型 | 加入背景     | "我是风控总监，分析这个方案"         | 30分 |
| L3 - 约束型   | 加入决策边界 | "预算500万，3个月试点，评估是否合作" | 60分 |
| L4 - 结构型   | 指定输出格式 | "输出执行摘要+详细报告+行动清单"     | 80分 |
| L5 - 系统型   | 闭环迭代     | "分3轮迭代，每轮更新风险+决策树"     | 95分 |

  您当前在 L3-L4 之间，已经超越90%的用户。

  要达到 L5，核心是:

1. 动态性: 不是一次性分析，而是持续迭代
2. 概率化: 不是"高风险"，而是"30%概率×100万损失"
3. 可迁移: 不只解决这个问题，还沉淀方法论
4. 闭环验证: 不只给建议，还告诉你"如何验证建议是否有效"

---

  最后的建议:

  不要追求"完美的Prompt"，而要追求"适合当前任务的Prompt"。

  简单任务用L2，复杂决策用L4，长期学习用L5。

  Prompt工程的本质是思考的外化——
  你想得越清楚，AI答得越精准。

  祝您在Prompt工程的道路上不断精进! 🚀
